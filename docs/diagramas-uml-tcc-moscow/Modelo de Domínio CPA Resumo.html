Como ler os diagramas

A notação segue UML 2.5. Nomes em itálico indicam classes e operações abstratas; os símbolos +, - e # antes de cada membro marcam visibilidade pública, privada e protegida.

Generalização (herança) Triângulo vazado apontando para a superclasse. SecaoAgrupadora → ComponenteSecao.
Composição Losango preenchido no todo. A parte não sobrevive ao todo: apagar o relatório apaga suas respostas.
Agregação Losango vazado. A parte existe por conta própria: dissolver a comissão não apaga os usuários.
Associação direcionada Referência simples, sem posse. Resposta aponta para a seção que ela responde.
Dependência Linha tracejada. Os serviços usam as entidades sem guardá-las como atributo.
Multiplicidade Quantos objetos participam de cada ponta. 3..* na comissão reflete a exigência de composição mínima.

Onde cada tipo de relação aparece

As três relações estruturais do modelo foram escolhidas pelo critério de dependência existencial, não por conveniência de desenho.

RelaçãoTipoPor quê
Instrumento → ComponenteSecaoComposiçãoUma seção só faz sentido dentro da versão do instrumento que a definiu. Descartar o instrumento descarta a árvore inteira.
SecaoAgrupadora → ComponenteSecaoComposição reflexivaÉ o coração do Composite: a recursão da árvore de eixos, indicadores, critérios e subcritérios.
Relatorio → RespostaComposiçãoUma resposta não existe fora do relatório em que foi escrita.
Resposta → RespostaRevisaoComposiçãoO histórico é parte interna da resposta e morre com ela.
ComissaoCPA → UsuarioAgregaçãoO usuário tem vida própria no sistema: ele permanece quando o mandato da comissão termina.
ComponenteSecao → SecaoAgrupadora / SecaoFolhaGeneralizaçãoComposto e folha respondem às mesmas operações de formas diferentes — o que justifica o padrão.
Resposta → RespostaTexto / Ternaria / AnexoGeneralizaçãoOs requisitos legais respondem Sim/Não/Não se aplica; os eixos recebem texto dissertativo. Tipos distintos, contrato comum.
Relatorio → InstrumentoAssociaçãoO relatório referencia o instrumento, mas não o possui: o mesmo instrumento serve a várias IES e vários ciclos.
Nota sobre o Composite. A hierarquia trata da estrutura; a capacidade de receber resposta é um eixo separado, expresso pelo atributo tipoResposta. Assim um indicador pode ao mesmo tempo ter filhos e aceitar texto dissertativo, sem quebrar a separação entre composto e folha.

Da classe para a tabela

As hierarquias de herança usam Single Table Inheritance: cada árvore vira uma tabela com uma coluna discriminadora. É o mapeamento mais direto para o Eloquent e evita junções em toda leitura.

O atributo caminho. É um caminho materializado montado com os valores de ordem dos ancestrais, em segmentos de largura fixa. Um ORDER BY caminho devolve os 1.135 nós já na ordem do documento, o que torna a geração do PDF um laço linear em vez de uma travessia recursiva.
